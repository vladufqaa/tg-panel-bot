# tg-panel-bot

Telegram-панель для [x-ui](https://github.com/MHSanaei/3x-ui)-совместимой панели: одно «окно»
с inline-меню, навигация внутри окна без спама сообщениями, автообновление статуса.

Выделен из внутреннего набора скриптов как самостоятельный бот: **только панельные функции** —
ничего не устанавливает, не «чинит» и не меняет конфиг панели.

## Возможности

- 🖥 **Сервер** — статус x-ui, аптайм, load, RAM, диск, активные соединения на 443, RX/TX; автообновление каждые 10 с
- 👥 **Клиенты** — список с пагинацией; карточка клиента: подписка + QR, инбаунды, лимит ГБ, срок действия, вкл/выкл, удаление (с подтверждением)
- ➕ Мастер создания клиента (инбаунды → трафик → срок → имя) через API панели; ссылка и QR сразу после создания
- 🚦 **Трафик** — по клиентам + RX/TX сервера
- 📡 **Инбаунды** — список из БД панели
- 🛠 **Обслуживание** — рестарт x-ui / Xray, бэкап БД, журналы ошибок (x-ui, сам бот, любой юнит по имени)
- ⏰ **Бэкап БД** — вручную кнопкой или по расписанию (systemd-timer присылает документ в чат)
- 🕵️ **Мониторинг** (настраивается в «Расписание») — алерты: сбой Xray, узел недоступен (443), исходящие в интернет, CPU/RAM, диск, серты ≤7 дней, упавший бэкап, попытки входа в панель

## Требования

- Linux + bash + systemd (сервис и таймер бэкапа)
- `jq`, `curl`, `sqlite3`, `flock` (util-linux); `qrencode` — для QR-картинок
- Панель x-ui/3x-ui с включённым API и токеном (см. ниже)

## Установка

```bash
sudo install -m 755 tg-panel-bot.sh /root/tg-panel-bot.sh

sudo tee /root/.tg-panel-bot.env >/dev/null <<'EOF'
BOT_TOKEN=123456789:AA...
ADMIN_CHAT_ID=123456789
EOF
sudo chmod 600 /root/.tg-panel-bot.env

sudo cp install/tg-panel-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tg-panel-bot
```

### Токен панели API

Бот обращается к API панели с Bearer-токеном. По умолчанию читает его из
`/root/.tg-api-token` (в файле — только сам токен, одной строкой). Альтернатива —
переменная `XUI_API_TOKEN` в env-файле.

В 3x-ui-форках токен обычно создаётся так (каждый вызов перегенерирует токен —
выполняйте один раз и сразу сохраняйте результат):

```bash
/usr/local/x-ui/x-ui setting -getApiToken   # последняя строка «apiToken: …» → в файл
```

## Конфигурация (env-файл)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | токен бота от @BotFather (обязателен) |
| `ADMIN_CHAT_ID` | — | ID владельца (обязателен; узнать — @userinfobot) |
| `TG_PROXY` | — | SOCKS-прокси для Telegram API, напр. `socks5h://127.0.0.1:1080` |
| `XUI_DB` | `/etc/x-ui/x-ui.db` | путь к БД панели |
| `XUI_API` | `https://127.0.0.1:2904` | базовый URL API панели (Host подставляется из `subDomain` в БД) |
| `XUI_API_TOKEN` | — | токен API (иначе файл `XUI_API_TOKEN_FILE`) |
| `XUI_API_TOKEN_FILE` | `/root/.tg-api-token` | файл с токеном API |
| `SUB_PATH` | из БД (`subURI`) или `podpiska` | путь подписочных ссылок |

Сообщения от кого-либо, кроме `ADMIN_CHAT_ID`, молча игнорируются.
Если `ADMIN_CHAT_ID` не задан, бот работает в «режиме обучения»: пишет приходящие
`chat_id` в журнал (`journalctl -u tg-panel-bot`) и никому не отвечает.

## Поведение и безопасность

- Бот читает БД панели и вызывает её API; systemd-юниты создаёт только по явному нажатию
  кнопок в «Расписании» бэкапа.
- Деструктивные действия (удаление клиента) — с подтверждением ✅/❌.
- Один экземпляр через `flock` (два поллера получают 409 от Telegram), курсор апдейтов
  переживает рестарт — старые нажатия не переигрываются.
- Уведомления при вкл/выкл клиента не шлются специально: фидбек — обновление карточки.

## Примечания

- Расписание бэкапа создаёт юниты `tg-panel-bot-backup.service/.timer`; таймер запускает
  `tg-panel-bot.sh --backup` — бот сам делает sqlite-копию БД и шлёт её документом.
- Все тексты и меню — на русском.
